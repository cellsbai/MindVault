# 任务一览开发计划

> 范围：仅覆盖「任务一览」「任务编辑」「Temporal 配置读写」「自定义任务（租户级覆盖）」四部分。

## 一、前置约定

- 数据源存储到DB中，然后新建时定时任务时，先落库，没问题后再发送temporal接口。
- 后端使用 `zf-server-infra` 中提供的 temporal 操作 temporal，如果缺少可以补充进去。
- 前端代码放入 `admin-web` 中。
- 后端代码放入 `main-server` 中。
- namespace 目前写死 [shoteyes]

### 3. 更新接口
> 保存时，先调用temporal进行修改配置，修改成功后再进行落库，temporal中schedule的input值为: params + taskId + options
- 接口：`PUT /api/schedule/update`
- 参数：
	```json
	{
		data: {
			taskId: '',
			enabled: false,
			cron: '',
			params: {},
			description: [],
			options: {}
		}
	}
	```
- 校验：
  - cron 合法性

**验收**：修改完后应跟temporal的配置对应上，先保存目标配置和待同步状态，再同步，如果temporal报错，数据库保留目标配置，记录同步失败。
### 4. 删除接口
> 先记录待删除，同步成功后软删除
- 接口：`DELETE /api/schedule/remove`
- 参数：`id`
**验收**：删除后，Temporal Web UI 上应该一同消失。

### 5. 新增接口
> temporal中schedule的input值为: params + taskId + options
- 接口：`POST` /api/schedule/add
```json
	{
		data: {
			scheduleId: '',
			namespace: '',
			taskId: '',
			enabled: false,
			cron: '',
			params: {},
			options: {},
			description: ''
		}
	}
```

**验收**：新增后，Temporal Web UI 上应该出现一条定时任务。

### 6. 同步接口
POST /api/schedule/sync
参数：id
行为：读取数据库中的目标配置和 syncAction，执行对应同步操作。
## 数据库与 Temporal 同步规则

### 1. 基本原则

- 数据库保存任务的目标配置，Temporal 负责实际调度执行。
- 创建、更新、删除均先保存数据库，再立即尝试同步到 Temporal。
- 数据库保存成功不代表 Temporal 已生效，以同步状态为准。
- 同步成功后，将同步状态更新为“已同步”；同步失败时，记录失败原因。
- 不增加后台自动同步或自动重试，未完成的操作由管理员点击「同步」手动重试。

### 2. 同步信息

任务记录增加以下信息：

| 字段 | 说明 |
| --- | --- |
| `syncStatus` | 同步状态：待同步、已同步、同步失败 |
| `syncAction` | 待执行操作：创建、更新、删除；同步完成后清空 |
| `syncError` | 最近一次同步失败原因；重新同步成功后清空 |

目标配置与待执行操作、同步状态必须在同一次数据库写入中保存，
避免出现配置已变更但没有待同步标记的情况。

### 3. 三种操作的规则

#### 创建

1. 校验参数及 `scheduleId` 唯一性。
2. 保存完整任务配置，标记为“待同步”，待执行操作为“创建”。
3. 调用 Temporal 创建 Schedule，创建时直接应用目标启用或停用状态。
4. 成功后标记为“已同步”；失败时保留数据库记录，标记为“同步失败”并记录原因。
5. 手动重试复用原 `scheduleId`，不得生成新的任务 ID 或重复插入数据库记录。

#### 更新

1. 根据任务数据库 ID 定位记录，将提交字段合并为完整目标配置。
2. 未提交字段保持原值，不能因只修改启停状态而清空其他配置。
3. 保存目标配置，标记为“待同步”，待执行操作为“更新”。
4. 使用 Temporal 原地 `update` 修改 Schedule，不得通过删除重建实现更新。
5. 成功后标记为“已同步”；失败时保留目标配置，标记为“同步失败”并记录原因。
6. Temporal 中目标 Schedule 不存在时，提示管理员处理，不自动转为创建。

#### 删除

1. 先在数据库中标记为“待同步”，待执行操作为“删除”，保留任务记录。
2. 调用 Temporal 删除 Schedule。
3. Temporal 删除成功后，再完成数据库软删除，从正常列表移除。
4. Temporal 中 Schedule 已不存在时，视为删除目标已达成，继续完成数据库软删除。
5. 删除失败时保留记录，标记为“同步失败”，允许通过「同步」重试删除。

### 4. 失败处理

#### 第一步数据库保存失败

- 不调用 Temporal。
- 返回保存失败，页面保留管理员输入，允许重新提交。

#### Temporal 明确返回参数错误或权限错误

- 保留数据库中的目标配置和待执行操作。
- 将同步状态更新为“同步失败”，记录并展示可理解的错误原因。
- 参数错误由管理员修正配置后重新提交。
- 权限错误在相关权限恢复后，由管理员点击「同步」重试。
- 不自动回滚数据库配置，不自动重试。

#### 调用超时或结果不确定

- 不将请求超时直接认定为 Temporal 未执行。
- 下次手动同步时，先通过 `describe` 查询实际配置，再决定是否执行操作。
- 如目标配置已经生效，仅补记同步成功。
- 创建时发现同名 Schedule，必须确认属于本次创建，不能直接覆盖无关任务。
- Temporal 已成功但数据库同步状态更新失败时，保留未完成状态，
  下次手动同步通过查询实际结果补齐数据库状态。

### 5. 一览页面

- 增加「同步状态」列，与「启用／停用」状态分开展示。
- 启用／停用表示数据库中的目标配置；未同步时不得暗示该配置已经生效。
- 同步状态展示：
  - 待同步：配置已保存，尚未确认生效。
  - 已同步：最近一次操作已成功同步到 Temporal。
  - 同步失败：展示失败状态，并提供查看失败原因的入口。
- 待删除记录继续保留在列表中，明确展示“待删除”；
  删除失败时提示“删除未完成，任务可能仍会触发”。
- 对“待同步”“同步失败”的任务，在操作栏提供「同步」按钮。
- 点击「同步」后，根据记录中的待执行操作，重试创建、更新或删除。
- 同步期间按钮显示加载状态，禁止重复提交；
  后端也必须保证同一任务不能同时执行多个同步操作。
- 同步成功后刷新当前列表；删除成功后移除对应记录。
- 同步失败时更新失败原因，保留「同步」入口。

### 6. 未完成操作的限制

- 存在未完成操作时，不接受其他新的变更操作，避免覆盖尚未完成的同步意图。
- 对已确认的参数错误，允许修正同一次创建或更新的目标配置后重新提交。
- 同步结果不确定时，先通过「同步」核对实际状态，再进行其他修改。
- 服务重启后仍保留未完成记录，管理员可继续手动同步。
## 三、前端开发任务

### 1. 任务一览页面

- 筛选条件：任务描述 + 命名空间（默认巡店） + 搜索按钮，使用 `LightFilter` 方式。
- 操作组件：新建定时任务
- 列表组件：表格展示。
  - 任务 ID
  - 命名空间
  - 任务描述
  - 执行计划：cron 直接展示即可
  - 下次执行：下 5 次执行时间，换行展示 +08:00 加上当前本地的时区
  - 状态：switch 开关，启用/停用
  - 操作按钮：编辑、删除
- 列表分页展示，默认分页条数20条。
- 状态快捷操作：列表行内直接提供「暂停/启用」toggle 接口，调用 `update` 接口，只传 `enabled` 字段，不用进详情页面。点击增加一个确认提示
- 任务描述搜索在前台直接搜索，不用后台搜索。

#### 任务执行参数与租户范围提示
- 任务执行参数使用 JSON 文本输入框编辑，保存到 `params` 字段。
- 对支持租户筛选的任务，在输入框上方常驻展示以下说明：
  - `codes`：仅执行指定租户；不填或为空数组时，执行全部在用租户。
  - `excludeCodes`：从全部在用租户中排除指定租户。
  - `codes` 非空时，`excludeCodes` 不生效。
  - 租户值填写租户编码。
- 对不支持租户筛选的任务，明确显示“该任务不支持通过 codes / excludeCodes 筛选租户”，
  不提供租户参数示例入口。

**租户参数示例**

输入框右上方提供「填入租户参数示例」下拉按钮，包含：

- 仅执行指定租户：填入 `"codes": ["租户编码"]`。
- 排除指定租户：填入 `"excludeCodes": ["租户编码"]`。

填入示例时保留其他参数。对应字段已有值时不覆盖，仅提示填写示例。
当前 JSON 格式错误时，提示先修正格式，不修改输入内容。

**执行范围摘要**

输入框下方根据参数实时展示执行范围：
- `codes`、`excludeCodes` 均未填写或为空数组：显示“全部在用租户”。
- `codes` 非空：显示“仅 tenant-a、tenant-b”。
- `codes` 未填写或为空数组，且 `excludeCodes` 非空：
  显示“全部在用租户，排除 tenant-a、tenant-b”。
- 两者均非空：按 `codes` 展示范围，并提示“已指定 codes，excludeCodes 当前不生效”。

**校验与验收**
- 参数必须是合法的 JSON 对象。
- `codes`、`excludeCodes` 如有填写，必须是由非空租户编码字符串组成的数组。
- 参数格式错误时显示具体错误，执行范围显示“参数格式有误，暂无法确定”，并禁止保存。
- 前后端均校验参数；保存后实际执行范围应与页面摘要一致。
- 示例填入不得覆盖已有字段或丢失其他任务参数。

**验收**：启用暂停、搜索均正常工作。

### 2. 任务编辑页面

使用 Editor 侧拉窗。

只读信息区：
- 任务 ID
可编辑区：
- 描述
- 执行任务ID
- 启用、暂停：Switch 组件。
- 执行时间：可视化选择器，支持每天、每周、每月、Cron 表达式。
- 每天：执行时间内部转换成 cron 表达式。
- 每周：下拉多选周几 + 执行时间，内部转换成 cron 表达式。
- 每月：下拉多选每日 + 执行时间，内部转换成 cron 表达式。
- Cron 表达式：input 输出框。
- 任务执行参数：JSON textarea输入框，平铺在Input第一层
- 展示区：改动完执行时间后，自动展示下 5 次执行时间，使用 AgGrid 展示，格式为 `YYYY-MM-DD HH:mm:ss`+08:00 加上当前本地的时区，应转换成当前时区进行展示；编辑进入时也自动展示下 5 次执行时间。
- 高级配置： 展示（单次执行超时、 首次重试等待时间、重试间隔增长倍数、最大重试等待时间、最大尝试次数）带事件的 都改为 左侧输入右侧下拉选(分钟、小时)
	其默认值为，存储格式如下
	```json
	"startToCloseTimeout": "3 hours",
	"retry": {
		"initialInterval": "1 minute",
		"backoffCoefficient": 2,
		"maximumInterval": "10 minutes",
		"maximumAttempts": 1
	}
	```
- 保存按钮：调用 `update` 接口，提交前做前端基础校验。
- 保存成功/失败提示。
### 3. 新建任务页面
公用编辑页面，任务ID在新建时才允许编辑，默认启用开关时关闭的，如果打开后点击保存，提示 “目标方法是否已经部署好了”的一个提示，这个需要你再优化下提示

## 四、Worker重启规则
> 目前shoteyes-server启动时，会注册temporal，然后再启动worker

- 目前注册的地方在main-server中实现了，业务系统中只需要启动worker即可，所以要移除注册temporal的代码，一并移除关联且无用的代码
- jobId改为taskId

## 五、验收清单
- [ ] 列表页数据与 Temporal 实际状态一致，全量展示无遗漏。
- [ ] 暂停/启用操作实时生效，DB、Temporal Web UI 可验证。
- [ ] cron修改后，下次触发时间符合预览展示。
- [ ] scheduleId是唯一的，不管是新建、还是更新，都要保证是唯一的存在
- [ ] 业务系统不应该存在注册的逻辑，只有启动worker的逻辑
- [ ] Worker 启动时不得使用代码默认配置覆盖管理员保存的配置。
