# 定时任务管理页面 - 代码开发计划

> 范围：仅覆盖「任务一览」「任务编辑」「Temporal 配置读写」「自定义任务（租户级覆盖）」四部分。

---

## 一、技术选型与前置约定

| 项目          | 说明                                                                                |
| ----------- | --------------------------------------------------------------------------------- |
| 数据源         | Temporal 作为唯一配置真源，不落 DB 存配置                                                       |
| 后端          | Node.js + `@temporalio/client`                                                    |
| 可编辑字段（共同任务） | 启用/暂停、执行时间（cron+时区）、允许租户                                                          |
| 只读字段        | Schedule ID、Workflow 类型、Task Queue、执行方法                                           |
| 排除租户字段      | 系统内部维护，不开放页面直接编辑，仅由「自定义任务」创建/取消流程自动读写                                             |
| 租户过滤        | 编码进 `Schedule.action.args`，由 Workflow 内部读取并过滤（依赖阶段外的 Worker 侧改造，本计划仅负责把参数写进 args） |
| 列表展示        | 不分页，全量展示                                                                          |

## 二、后端开发任务

### 2.1 Temporal 访问层封装

**目标**：统一封装对 Temporal Schedule API 的读写，业务层不直接碰 SDK。

- [ ]  `TemporalScheduleService` 封装以下方法：
    - `listSchedules(filter?: { taskQueue?, keyword? })`：调用 `ScheduleClient.list()`，应用层过滤，全量返回（不分页）
    - `getScheduleDetail(scheduleId)`：调用 `DescribeSchedule`，返回完整字段（含 `args` 解析出的允许/排除租户列表、`memo` 解析出的父子关联信息）
    - `updateSchedule(scheduleId, patch)`：基于 `handle.update(prev => {...})` 回调模式实现，只合并允许修改的字段，避免整体覆盖
    - `pauseSchedule(scheduleId, note?)` / `unpauseSchedule(scheduleId, note?)`：单独封装，语义清晰，不复用 update
    - `createCustomSchedule(parentId, { tenantId, cron, timezone })`：新建自定义 Schedule，继承父任务只读字段，设置 `args.allowedTenants=[tenantId]`，设置 `memo={ parentScheduleId, tenantId, isCustom: true }`
    - `deleteCustomSchedule(customId)`：删除自定义 Schedule
- [ ]  定义字段白名单常量（哪些字段允许通过 API 写入），后端强制校验，防止绕过前端直接改骨架字段
- [ ]  处理 `args` 与「允许租户」「排除租户」字段的编解码
- [ ]  处理 `memo` 与父子关联信息的编解码
- [ ]  异常处理：Schedule 不存在、Temporal 连接失败、update 并发冲突（基于 SDK 回调机制天然处理，需补充友好错误码）

**验收**：单元测试覆盖 list/detail/update/pause/unpause/createCustom/deleteCustom 全部分支，mock Temporal Client。

---

### 2.2 列表 API

- [ ]  `GET /api/temporal/schedules`
    - query 参数：`taskQueue`、`keyword`（匹配 scheduleId/workflowType）
    - 全量返回，不分页
    - 返回字段：scheduleId、workflowType、taskQueue、enabled（由 `state.paused` 取反）、nextRunTime、cron、timezone、**isCustom**（是否为自定义任务）、**parentScheduleId**（若为自定义任务，指向所属共同任务）
- [ ]  性能：避免 N+1 调用 `DescribeSchedule`，列表页只用 `List` 返回的精简信息（含 memo，用于判断 isCustom），租户明细留到详情页

**验收**：接口联调通过，全量任务（含自定义子任务）一次性返回，前端能正确区分共同任务和自定义任务。

---

### 2.3 详情 API

- [ ]  `GET /api/temporal/getSchedule`
    - 调用 `getScheduleDetail`，返回完整信息，包含解析后的「允许租户」「排除租户」列表
    - 若为共同任务：额外返回「已被哪些租户自定义」列表（通过 `parentScheduleId` 反查所有子 Schedule，或直接用父任务的 `excludedTenants` 反推）
    - 若为自定义任务：额外返回所属共同任务的基础信息（scheduleId、cron，便于前端展示"来自共同任务 xxx"）
    - 只读字段（Schedule ID、Workflow 类型、Task Queue、执行方法）一并返回，前端仅展示不提供编辑
- [ ]  `GET /api/schedules/:id/next-runs?count=5`
    - 基于传入的 cron + timezone（未保存的草稿值也要支持预览），计算未来 N 次执行时间
    - 用于编辑页「保存前预览」功能，也用于「新建自定义任务」表单的预览

**验收**：详情页数据完整；共同任务能看到自己被哪些租户自定义了；自定义任务能看到自己的父任务信息；next-runs 接口能正确处理草稿态参数。

---

### 2.4 更新 API（共同任务 / 自定义任务通用字段修改）

- [ ]  `PATCH /api/temporal/updateSchedule`
    - 请求体仅允许：`enabled`、`cron`、`timezone`、`allowedTenants`（自定义任务的 `allowedTenants` 固定为单租户，不允许通过此接口修改，仅共同任务可编辑该字段）
    - 后端二次校验字段白名单，非法字段直接 400，不静默忽略
    - cron 合法性校验（格式、频率下限，例如拒绝"每分钟触发"这类，除非有额外开关）
    - 内部调用 `updateSchedule` / `pauseSchedule` / `unpauseSchedule`（根据 `enabled` 字段变化路由到对应方法）
    - 更新成功后，写入审计日志（见 2.6）
- [ ]  并发冲突处理：基于 `handle.update()` 回调内读取最新 `prev` 状态再合并，天然避免覆盖式写坏；如底层抛出冲突异常，返回明确错误码前端提示「请刷新后重试」

**验收**：修改单个字段能正确同步到 Temporal，可在 Temporal Web UI 上验证结果；非法字段/非法 cron 被正确拦截；自定义任务的 allowedTenants 无法被此接口修改。

---

### 2.5 自定义任务创建/取消 API（新增）

- [ ]  `POST /api/temporal/schedules/:parentId/custom`
    - 请求体：`{ tenantId, cron, timezone }`
    - 前置校验：该 `tenantId` 是否已在其他自定义任务中存在（防重复自定义同一租户）
    - 执行步骤（需保证顺序，第二步失败要回滚第一步）：
        1. 调用 `createCustomSchedule` 新建自定义 Schedule，ID 规则：`${parentId}__custom__${tenantId}`
        2. 更新父任务（共同任务）的 `excludedTenants`，追加该 `tenantId`
        3. 若步骤 2 失败：删除步骤 1 刚创建的自定义 Schedule，返回明确错误提示用户重试
    - 成功后写入审计日志（记录「创建自定义任务」这一操作，关联父任务 ID）
- [ ]  `DELETE /api/temporal/schedules/:parentId/custom/:tenantId`
    - 执行步骤：
        1. 删除对应的自定义 Schedule（`${parentId}__custom__${tenantId}`）
        2. 更新父任务的 `excludedTenants`，移除该 `tenantId`
    - 成功后写入审计日志（记录「取消自定义任务」这一操作）
- [ ]  幂等性：重复调用创建接口（同一租户已存在自定义任务）应返回明确的「已存在」错误，而不是静默覆盖或报未知错误

**验收**：新建自定义任务后，共同任务的排除列表正确更新，两者在 Temporal 上均可验证；取消自定义后，两个 Schedule 状态正确回退；模拟步骤 2 失败场景，验证回滚逻辑生效。

---

### 2.6 审计日志

- [ ]  建表（见下方 DDL）
- [ ]  在 `PATCH /api/temporal/updateSchedule` 与 2.5 的创建/取消接口中，统一写入审计记录：
    - 字段修改：记录字段级 diff（field_name/old_value/new_value）
    - 创建自定义任务：记录 `action=CREATE_CUSTOM`，关联 parentScheduleId、tenantId、cron
    - 取消自定义任务：记录 `action=DELETE_CUSTOM`，关联 parentScheduleId、tenantId
- [ ]  `GET /api/schedules/:id/audit-logs`：查询某个任务的历史变更记录，按时间倒序

```sql
CREATE TABLE schedule_audit_log (
  id SERIAL PRIMARY KEY,
  schedule_id VARCHAR(255) NOT NULL,
  action VARCHAR(32) NOT NULL DEFAULT 'UPDATE_FIELD', -- UPDATE_FIELD / CREATE_CUSTOM / DELETE_CUSTOM
  field_name VARCHAR(64),
  old_value TEXT,
  new_value TEXT,
  related_tenant_id VARCHAR(255),
  changed_by VARCHAR(255) NOT NULL,
  changed_at TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX idx_schedule_audit_log_schedule_id ON schedule_audit_log(schedule_id);
```

**验收**：任意一次字段修改、自定义任务创建/取消，均能在审计表查到对应记录，且新旧值/关联信息准确。

## 三、前端开发任务

### 3.1 任务一览页

- [ ]  列表组件：表格展示 scheduleId、所属 Task Queue、状态（运行中/已暂停，带颜色区分）、下次执行时间、cron 原文、**类型标签**（共同任务 / 自定义任务）
- [ ]  自定义任务行：额外展示「所属共同任务」列（可点击跳转到父任务详情）
- [ ]  筛选栏：Task Queue 下拉筛选、关键字搜索（scheduleId、描述）
- [ ]  全量展示，不分页（数据量增长后如有性能问题，后续再评估虚拟滚动等方案，本期不做）
- [ ]  状态快捷操作：列表行内直接提供「暂停/启用」toggle（调用 `PATCH` 接口的 `enabled` 字段），不用进详情页

**验收**：能正确展示全部任务（含自定义子任务），筛选/搜索/行内暂停启用均正常工作，自定义任务能清晰看出归属。

---

### 3.2 任务编辑页（详情页）

- [ ]  只读信息区：Schedule ID、Workflow 类型、Task Queue、执行方法，纯展示，不提供输入框
- [ ]  可编辑区（仅共同任务展示完整编辑区；自定义任务仅展示启用/暂停 + cron/时区，允许租户固定为单租户不可编辑）：
    - 启用/暂停：Switch 组件
    - 执行时间：可视化选择器（每天/每周/每月 + 时间点），内部转换成 cron 表达式，同时提供时区下拉
    - 允许租户：多选组件，支持搜索租户名称，展示当前已选列表（仅共同任务可编辑）
- [ ]  「预览未来执行时间」区块：编辑 cron/时区后，实时调用 `next-runs` 接口，展示未来 5 次预计执行时间，保存前用户可核对
- [ ]  保存按钮：调用 `PATCH` 接口，提交前做前端基础校验
- [ ]  保存成功/失败提示；失败时如果是并发冲突，提示刷新页面重新编辑

**验收**：编辑保存后，页面展示与 Temporal 实际状态一致。

---

### 3.3 自定义任务模块（新增）

- [ ]  共同任务详情页新增「自定义」按钮，点击弹出表单：
    - 选择租户（下拉/搜索，排除已经自定义过的租户）
    - 设置 cron（复用 3.2 的可视化选择器组件）+ 时区
    - 「预览未来执行时间」同 3.2
    - 提交后调用 `POST /api/temporal/schedules/:parentId/custom`
- [ ]  共同任务详情页新增「已自定义租户」列表区块：
    - 展示每个已自定义租户的 cron、下次执行时间
    - 每行提供「取消自定义」按钮，点击调用 `DELETE` 接口，需二次确认弹窗（避免误触）
- [ ]  自定义任务详情页展示「所属共同任务」信息（scheduleId + cron），并提供跳转链接
- [ ]  创建/取消自定义任务的成功/失败提示（尤其是后端回滚场景，需明确告知用户"创建失败，未产生数据变更，请重试"）

**验收**：共同任务能正确创建/查看/取消租户自定义任务；创建后共同任务的排除列表与自定义任务的执行时间均在 Temporal 上验证一致；取消后两者正确回退到默认状态。

## 五、验收清单（联调完成后逐项核对）

- [ ]  列表页数据与 Temporal 实际状态一致，全量展示无遗漏
- [ ]  暂停/启用操作实时生效，Temporal Web UI 可验证
- [ ]  cron/时区修改后，下次触发时间符合预览展示
- [ ]  共同任务允许租户修改后，`args` 正确更新
- [ ]  骨架字段（Schedule ID/Workflow 类型/Task Queue/执行方法）无法通过页面或直接调 API 修改
- [ ]  非法 cron、非法字段均被后端正确拦截，不静默失败
- [ ]  任意一次修改、自定义任务创建/取消，均能在审计日志中查到完整记录
- [ ]  并发编辑场景下不会出现无提示的覆盖式写坏
- [ ]  创建自定义任务后，共同任务的 `excludedTenants` 正确包含该租户，两个 Schedule 不会对同一租户重复触发
- [ ]  取消自定义任务后，共同任务的 `excludedTenants` 正确移除该租户，自定义 Schedule 被彻底删除
- [ ]  重复对同一租户创建自定义任务时，返回明确的「已存在」提示，不产生脏数据
- [ ]  模拟自定义任务创建流程第二步失败，验证第一步已创建的 Schedule 被正确回滚删除
