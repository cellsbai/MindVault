# 策略与系统配置

## 策略数据源

最终不再调用 `/api/v1/open/tenant-strategies`。每次小时同步结果时，直接从 `/api/v1/open/inspection/results` 的以下字段提取策略：

- `strategyCode`：唯一匹配键，必需；
- `strategyName`：策略名称；
- `tenantStrategyName`：租户策略展示名称。

同一批结果按去除首尾空格后的 `strategyCode` 去重。已存在的策略更新名称，新策略新增到 Mongo。页面展示名称优先级为：

1. `tenantStrategyName`；
2. `strategyName`；
3. `strategyCode`。

## Mongo 数据

集合模型为 `XinrongjiFruitStrategy`，业务字段只保留：

- `strategyCode`；
- `strategyName`；
- `tenantStrategyName`；
- 通用有效性和审计字段。

已经明确不需要的字段：

- `sourceCreatedAt`；
- `sourceUpdatedAt`；
- `sourceData`；
- `archivedAt`；
- 以 `tenantStrategyId` 为核心的历史冗余字段。

策略列表接口为 `POST /api/xinrongjiFruitStrategy/list`，供模板插件和看板 context 使用。

## 模板定制插件

插件仅对 `xinrongji` 开放。

| 项目 | 口径 |
| --- | --- |
| 名称 | 果实检测策略（不合格时自动生成整改） |
| 字段文案 | 请选择果实检测策略 |
| 交互 | 下拉单选、可搜索、可清空 |
| 数据结构 | 对象内保存 `strategies` 数组 |
| 当前最大选择数 | 1 |

模板题目扩展字段示例：

```json
{
  "custom_fruit_inspection_strategy": {
    "strategies": ["strategy-code"]
  }
}
```

对象加数组的结构用于后续扩展。当前页面只允许单选，但服务端周汇总应按数组读取，不能将其当成字符串。

支持的巡检题型：

- 检查项；
- 选项题；
- 分数输入；
- 数量输入。

## 策略与报告题目匹配

- 使用 `strategyCode` 匹配果实违规与模板题目；
- 同一策略配置到多个题目时，全部命中题目都标记为不合格；
- 同一题目配置多个策略时，合并这些策略的违规数量；
- 未配置到任何模板题目的策略仍参与周通知统计，但不生成报告题目；
- 模板必须同时满足 `valid=1`、`active=true` 且至少有题目配置该插件。

## 系统设置

系统设置页面仅对新荣记展示两个角色多选项，选项复用系统已加载的角色列表。

| 设置项 | Key | 保存格式 | 当前用途 |
| --- | --- | --- | --- |
| 果实检测小时汇总通知角色 | `fruitInspectionHourlyNoticeRoles` | JSON 角色 ID 数组 | 小时通知接收人 |
| 果实检测每周汇总通知角色 | `fruitInspectionWeeklyNoticeRoles` | JSON 角色 ID 数组 | 周通知接收人 |

两项默认值均为 `[]`，通过 `xinrongji.setting.parse` 和 `xinrongji.setting.serialize` 接入现有 `/api/tenant/settings`。

## 空配置行为

- 小时角色未配置：仍完成数据同步，只跳过小时飞书通知。
- 周角色未配置：仍生成周报告和整改，只跳过周飞书通知。
- 策略字典暂时为空：模板下拉无可选项；不应人工写入与果实结果不一致的代码。
- 模板没有命中策略：该策略只进入周通知统计，不生成报告。
