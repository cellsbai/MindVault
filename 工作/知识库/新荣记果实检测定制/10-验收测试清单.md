# 验收测试清单

## 小时同步

- [ ] 首次同步从上海时间当天 `00:00:00` 开始。
- [ ] 后续同步从上次成功时间向前重叠 5 分钟。
- [ ] `dateFrom`、`dateTo` 精确到秒，格式正确。
- [ ] 结果超过 100 条时可拉取全部分页。
- [ ] 空结果成功时仍推进游标。
- [ ] 果实 API、OSS 或 Kafka 失败时不推进游标。
- [ ] 429、5xx、网络错误最多重试 3 次。
- [ ] 401、403、422 不重试。
- [ ] Reporter 收到脱敏后的小时同步失败通知。
- [ ] 日志没有 API Key、App Secret、授权码或带签名 URL。

## OSS 和 Kafka

- [ ] 生产使用 `shoteyes`，非生产使用 `shoteyes-dev` 和 `devtmp/`。
- [ ] 图片、视频 Key 符合固定目录规则。
- [ ] 已有对象不重复下载和上传。
- [ ] 空图片和空视频可以正常发送。
- [ ] `images` 和 `videoUrl` 入库后为 OSS Key。
- [ ] Kafka Topic、message key 和单 item JSON 正确，无外层包装。
- [ ] 每批发送 100 条。
- [ ] `detectTime` 为 `YYYY-MM-DD HH:mm:ss.SSS`，Connect 可写入。
- [ ] 重叠窗口重复记录最终按 `resultId` 得到唯一有效结果。

## 策略和模板

- [ ] 策略只从检测结果的三个名称/代码字段同步。
- [ ] 不再请求租户策略接口。
- [ ] 相同 `strategyCode` 不重复新增。
- [ ] 策略名称变化后可以更新展示。
- [ ] 模板插件只对新荣记显示。
- [ ] 页面为单选，但保存为对象内 `strategies` 数组。
- [ ] 清空策略后保存结构合法。
- [ ] 周任务按 `strategyCode` 匹配，不使用 `tenantStrategyId`。

## 小时通知

- [ ] 无违规不发送。
- [ ] 小时角色为空不发送，但不影响同步。
- [ ] 只向同时命中角色和直属问题门店的人员发送。
- [ ] 未匹配或同名门店不参与通知。
- [ ] 每人数字只统计本人负责的问题门店。
- [ ] 同一问题门店的多个负责人各自计入该门店问题数。
- [ ] 相同负责门店集合的用户合并发送。
- [ ] 不同分组按 40 组一批发送，批次之间等待完成。
- [ ] 模板不含等级和涉及门店数。
- [ ] 统计时间使用真实开始、结束时间，格式为 `YYYY-MM-DD HH:mm 至 HH:mm`。
- [ ] 链接不含 `storeId` 和 `userId`。

示例验收：A 门店 4 项由张三负责，B 门店 4 项和 C 门店 2 项由李四负责，C 门店 2 项和 D 门店 6 项由王五负责；张三收到 4 项，李四 6 项，王五 8 项。

## 周报告和整改

- [ ] 每周一上海时间 09:45 统计上一自然周。
- [ ] 当前周无违规时不生成报告、整改和通知。
- [ ] 周查询不包含合规数据。
- [ ] 未匹配和同名门店跳过并告警。
- [ ] 每个门店、模板、周期只生成一份报告。
- [ ] 同一策略配置多个题目时全部题目不合格。
- [ ] 同一题目配置多个策略时合并违规数。
- [ ] 未配置模板的策略只进入通知统计。
- [ ] 报告不携带检测图片。
- [ ] 报告题目包含正确 `relatedLink`。
- [ ] 报告通过 `inspectionCtrl.singleCommit` 提交。
- [ ] 整改由标准提交流程按题目配置生成。
- [ ] 重复执行复用已有业务键报告。
- [ ] 并发执行风险和通知重复符合当前决策。

## 周通知

- [ ] 周角色为空时仍生成报告和整改，只跳过通知。
- [ ] 角色命中用户一次加载，不逐用户查询门店。
- [ ] 总部人员看到全部下属问题门店。
- [ ] 分区人员只统计分区下问题门店。
- [ ] 多所属组织人员取门店并集。
- [ ] 没有所属组织或无可见问题门店不发送。
- [ ] 每人违规数、门店数和上周对比只按本人可见门店计算。
- [ ] 持平、新增、上升、下降四种环比文案正确。
- [ ] 模板不显示等级。
- [ ] 链接不含 `storeId` 和 `userId`。

## 身份和权限

- [ ] App 链接有 `userId` 时跳过飞书 SDK。
- [ ] 飞书链接无 `userId` 时可完成授权码和用户映射。
- [ ] 飞书身份解析后地址栏不增加 `userId`。
- [ ] 复制飞书链接给其他人后按新打开人的权限查询。
- [ ] 普通浏览器无 `userId` 时禁止访问。
- [ ] 未绑定、重复绑定和无效用户明确报错，不回退全门店。
- [ ] 全组织、指定分区、普通所属组织和多组织并集正确。
- [ ] 返回的组织树只包含可见门店和必要祖先。
- [ ] 空 `storeId` 查询全部授权门店，不包含权限外门店。
- [ ] 分区、多个门店和混合选择都能正确展开、去重、取权限交集。
- [ ] 闭店、暂停营业、越权节点被忽略。

## 小时看板

- [ ] 页面只能从飞书或带 App 用户身份的链接正常进入。
- [ ] 默认时间为上一完整小时。
- [ ] 条件变化不查询，点击查询才生效。
- [ ] 点击清空不查询。
- [ ] 查询错误使用消息弹窗，不显示页面错误块。
- [ ] 只展示违规总数，不展示合格数据。
- [ ] 查询结果中没有合规记录。
- [ ] 上一等长时段的增加、减少、持平正确。
- [ ] 当前无数据时不显示对比和结果数。
- [ ] 有数据时显示 `共 N 条结果`。
- [ ] 明细每批 10 条，滚动后继续追加。
- [ ] 明细布局、红色边线、图片比例和移动端样式符合确认稿。
- [ ] 多图预览可以切换该条结果全部图片，点击一次直接放大。
- [ ] 空数据使用公共 Empty 组件并显示“暂无数据”。
- [ ] 策略、门店和日期选择器在手机端不弹键盘。

## 周看板

- [ ] 标题和浏览器 Tab 为“每周巡检汇总”。
- [ ] 本周数据统计在小屏置顶。
- [ ] 只展示违规总数，不展示合格率和进度条。
- [ ] 查询结果和图表不包含合规数据。
- [ ] 趋势图按日期和策略展示，高度不被压缩。
- [ ] 重点跟进展示全部项并按次数、最近时间、门店/问题稳定排序。
- [ ] 无重点数据时不显示“查看全部”。
- [ ] 查看全部保留当前策略、组织和日期进入小时页。
- [ ] 看明细只带入对应门店、策略和日期。
- [ ] 下钻小时页的结束时间覆盖结束日到 `23:59`。
- [ ] 移动端开始、结束日期拆分且不弹键盘。

## App 相关链接

- [ ] 新旧整改详情入口都支持相关链接。
- [ ] 相关链接位于承诺整改时间上方。
- [ ] `相关链接：` 与承诺整改时间冒号和行高一致。
- [ ] 操作文案为“点击查看”。
- [ ] WebView 标题为“每周巡检汇总”。
- [ ] 无 `relatedLink` 时不展示。
- [ ] 打开时保留原策略、门店、日期并追加当前用户 ID。
