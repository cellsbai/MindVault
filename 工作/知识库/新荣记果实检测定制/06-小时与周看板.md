# 小时与周看板

## 页面入口

| 页面 | 路由 | 标题和浏览器 Tab |
| --- | --- | --- |
| 小时汇总 | `/v2/analysis/fruitInspection/hourly` | 小时巡检汇总 |
| 周汇总 | `/v2/analysis/fruitInspection/weekly` | 每周巡检汇总 |

两页注册在 `shoteyes-web/src/remote/report.tsx`，不进入主菜单，不展示系统菜单和顶部 Header。页面主要从飞书通知、App 整改相关链接或周页内部下钻进入。

## URL 参数

| 参数 | 含义 | 格式 |
| --- | --- | --- |
| `strategyCode` | 果实策略 | 多值用逗号分隔 |
| `storeId` | 分区或门店组织 ID | 多值用逗号分隔 |
| `dateFrom` | 开始时间 | 上海时间 |
| `dateTo` | 结束时间 | 上海时间 |
| `keyword` | 问题或门店关键字 | 字符串 |
| `userId` | 巡店用户 Mongo `_id` | 只用于 App 入口初始化 |

历史参数 `tenantStrategyId` 已被 `strategyCode` 替代。飞书身份解析成功后，Web 只在内存请求中使用返回的用户 ID，不把它写回 URL，避免复制链接泄露身份。

## 筛选交互

两页筛选包含：关键词、策略多选、组织树多选和时间范围。

- 策略选项来自 context 返回的策略字典；
- 组织使用 TreeSelect，可混合选择分区和若干门店；
- TreeSelect 配置为多选、可勾选、父子严格选择并显示全部选中节点；
- 选择分区代表该分区下全部有权门店；
- 页面只展示当前访问人可见的组织节点及必要祖先；
- context 初始化后清除 URL 中无权或不存在的节点；
- 条件变化不自动查询，只有点击“查询”才发起请求；
- 点击“清空”只重置输入，不立即查询；
- 查询成功后才把已生效条件同步到 URL；
- 查询失败使用 `Base.message.error` 弹出，不在页面中显示错误文本；
- 右侧“展开筛选”入口始终保留。

移动端交互：

- 策略和门店选择器点击时不得唤起键盘；
- 日期输入为只读，点击日期选择器不得同时弹出键盘；
- 小屏周汇总将开始日期和结束日期拆成两个控件，避免面板被遮挡；
- 时间只选择到时、分，不显示秒；
- 日期弹层应在屏幕范围内完整展示。

## 查询默认值

- 小时页：默认上一完整小时；
- 周页：默认当前自然周，从本周一至当天；
- 飞书通知带入通知统计周期；
- App 报告链接带入报告关联门店、策略和周周期。

## 服务端查询口径

看板控制器通过 `board.yml + SQL/EJS + Rider` 查询 ClickHouse，不直接拼完整 SQL。

数据表：

```text
b37bc664b5a4.xinrongji.inspection_results FINAL
```

通用筛选：

- 检测时间在查询窗口内；
- 仅符合统一违规口径的数据；
- `fieldName` 属于最终授权门店名称；
- 可选 `strategyCode IN (...)`；
- 关键词匹配门店、问题类型、描述、租户策略名或策略名；
- 门店名称必须精确且全局唯一映射。

小时区间使用 `[dateFrom, dateTo)`。周页面的结束日期包含当天，服务端将结束日转换为次日零点作为排他上界。

当前期与上一等长周期的汇总可能并行查询。每次 ClickHouse 请求必须使用独立随机 Query ID，避免出现 `Query ... is already running`。

## 小时汇总页

### 顶部和指标

- 页面背景为浅灰，主体设置最大宽度并保留两侧背景边距；
- 标题下直接显示 `YYYY-MM-DD HH:mm～YYYY-MM-DD HH:mm`，不增加“统计时间范围”等描述；
- 只显示一张占满整行的“违规总数”卡片；
- 违规数字和图标使用巡店主题红色；
- 卡片上半部分包含文案、数字和右上角图标，下方单独一行显示上一时段对比；
- 当前无数据时不显示“较上一时段持平”。

### 检测明细

- 有数据时只显示 `共 {total} 条结果`，不再显示“当前显示 {count} 条”；
- 前端逻辑分页，每批追加 10 条，接口仍一次返回全部明细；
- 接近列表底部时自动追加下一批；
- 筛选变化并执行新查询后重置批次；
- 页面不增加明细内部滚动条，列表高度随内容自适应；
- 外层保持页面自然滚动。

每条明细严格包含：

- 问题标题；
- 门店名称；
- 检测时间；
- 摄像头名称；
- 问题描述；
- 右侧证据图片。

卡片左侧使用巡店主题红色边线。移动端图片保持原确认稿宽高比例，不强制正方形。

如果一条结果有多张图片，卡片可以只显示首张缩略图，但点击后必须一次把该条结果的全部图片传给预览组件，用户可在预览中切换所有图片。移动端点击缩略图应直接打开大图，不能先显示小眼睛再点击一次。

无数据使用项目公共 `Empty` 组件，文案为“暂无数据”。图片加载应有加载态，失败时显示可理解的占位。

## 每周汇总页

### 页面顺序

小屏下按以下顺序展示：

1. 标题、周期和筛选；
2. 本周数据统计；
3. 违规数量趋势；
4. 本周需重点跟进。

### 本周数据统计

- 只显示一张占满整行的“违规总数”卡片；
- 使用巡店主题红色；
- 显示与上一等长周期的增减或持平；
- 无合格率卡、无合格率接口数据、无进度条。

### 违规数量趋势

- 使用项目 `Charts` 组件；
- 按日期和策略展示分组柱状图；
- 保留图例、网格、日期点击高亮和响应式布局；
- 图表区域固定提供足够高度，当前目标高度为 350px，不能被移动端卡片布局压窄；
- 图例多时可分页或滚动，但不能挤压主要绘图区。

### 本周需重点跟进

- 展示全部聚合项，不限制前三条；
- 分组维度为门店、策略和问题类型；
- 首先按违规次数从多到少；
- 次数相同时按最近检测时间倒序；
- 再按门店和问题名称稳定排序；
- 展示序号、问题名称、门店、策略、出现次数和“看明细”；
- 不展示违规等级；
- 没有重点项时不显示“查看全部”。

“查看全部”进入小时页，携带当前策略、组织选择和起止日期。“看明细”进入小时页，携带该项的实际门店、策略和周期。两种跳转都保留当前内存身份；若入口最初来自 App，则继续携带 `userId`。

周页下钻到小时页时，结束日转换为当天 `23:59` 展示，内部边界默认减 1 秒，避免小时页只查询到结束日零点。

## 接口响应

小时响应：

- `dateFrom`、`dateTo`；
- `summary.violationCount`；
- `summary.previousViolationCount`；
- `items`：明细展示字段、OSS 图片 Key、映射后的巡店门店 ID。

周响应：

- `dateFrom`、`dateTo`；
- `summary.violationCount`；
- `summary.previousViolationCount`；
- `trend`：日期与策略的违规数量；
- `followups`：全部重点问题聚合项。

响应中不再提供或消费合格数、总检测数、合格率。
